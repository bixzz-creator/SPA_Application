■ Executive Summary

AccessHub is a production-style single page application designed for enterprise applicant verification records management. It enforces strict Role-Based Access Control (RBAC) across client views, routing, and backend REST APIs. The architecture implements modular Angular components, reactive forms, RxJS observables, artificial latency simulation, and automated test coverage.

02. Backend Architecture & REST API Design

Database Models (MongoDB)

  • User Model: Stores `userId`, `name`, `email`, `password` (hashed with salt), `role` (`ADMIN` | `GENERAL_USER`), `status` (`ACTIVE` | `INACTIVE`).
  • Record Model: Stores `recordId`, `title`, `category`, `status`, `owner`, `priority`, and `description`.

Security & Middleware

  • JWT Auth: Validates `Bearer` tokens on all private endpoints.
  • requireAdmin: Restricts user directory & global management to administrators.
  • Delay Simulator: Handles query parameter `?delay=ms` to simulate latency.
Method Endpoint Access Description
POST /api/auth/login Public Validates user ID, password, and active status; issues JWT token.
GET /api/records Authenticated Returns records filtered by ownership for General Users, or all for Admin.
POST /api/records Authenticated Creates a new verification record tagged with current user ownership.
PUT / DELETE /api/records/:id Owner / Admin Modifies or removes a record (RBAC checked).
GET /api/users Admin Only Retrieves full user management directory with status and roles.
PATCH /api/users/:id/status Admin Only Toggles account status between ACTIVE and INACTIVE.

03. Frontend Architecture & Angular Modules

Core & Shared Modules

  • AppRoutingModule: Shell wrapper using `LayoutComponent` for authenticated routes.
  • AuthGuard: Redirects unauthenticated visits to `/login`.
  • RoleGuard: Enforces `data: { role: 'ADMIN' }` protection.
  • AuthInterceptor: Injects `Authorization: Bearer `.
  • Shared Components: Reusable Spinner, Badges, and Dialogs.

Feature Modules (Lazy Loaded)

  • AuthModule: Two-panel login UI with credential quick-fill.
  • DashboardModule: Key stat cards and recent records via `forkJoin`.
  • RecordsModule: Table with debounce search, filters, and latency toggle.
  • AdminModule: User directory with modal creation and status toggles.
  • ProfileModule: Profile updates, password changes, and RBAC matrix.
⚡ Async Delay Simulation Feature: Both the Records and User Management views feature an interactive latency selector bar (0ms, 1000ms, 2000ms, 3000ms). When toggled, the frontend requests data with an artificial server delay, triggering clean loading spinner states and demonstrating async handling.
